# 授权网站 + 软件商业化落地清单与设计方案

> 目标：从「能跑」到「能卖、能收钱、能售后、能对账」。
> 现状：原授权后台（PHP/SQLite）+ 内嵌套餐/支付/用户管理；用户端根路径；
> 软件平台化授权（Alibaba / Amazon / 速卖通）、心跳、软件登录已通。

---

## 一、现状盘点

### 已具备（可用）
- 用户注册/登录、邮箱验证码/找回密码（SMTP 已配通）
- 套餐、订单、易支付、回调自动开通、续费叠加
- 套餐用户管理：改邮箱/密码、手动开通全权限、取消授权、删除
- 软件：平台/功能包授权、机器码绑定、7 天离线、心跳上报
- 原后台保留（授权/日志/审计/管理员）

### 上线商用前的关键缺口（P0）
| # | 缺口 | 风险 | 方案 |
|---|---|---|---|
| 1 | 真实支付未完整验证 | 钱收了不开通 / 重复开通 | 0.01 真付 + 回调幂等 + 订单对账脚本 |
| 2 | 无退款流程 | 客户投诉、支付渠道纠纷 | 后台退款（原路退回/手工标记）+ 退款单 |
| 3 | 无发票 | 企业客户无法报销 | 电子发票申请（抬头/税号/邮箱），后台统一开 |
| 4 | 管理员无 2FA/子账号 | 后台被撞库 | 管理员 TOTP + 角色权限（只读/财务/客服） |
| 5 | 无自动备份/恢复演练 | 数据库丢失=客户全丢 | 每日 SQLite/MySQL 备份到对象存储 + 恢复演练 |
| 6 | 无监控告警 | 支付/回调挂了不知道 | 健康检查、回调失败告警、每日收入异常告警 |
| 7 | 无服务协议/隐私政策/退款政策 | 支付渠道与合规风险 | 3 份法务文本 + 注册勾选 |
| 8 | 授权到期无提醒 | 续费率低 | 到期前 30/7/1 天邮件 + 站内提醒 |
| 9 | 回调幂等/签名/重放 | 重复开通/伪造 | 订单唯一约束 + 回调去重 + 时间戳窗口 |

### P1（商业运营）
- 优惠券/邀请码、限时活动
- 微信支付 + 支付宝双通道
- 订单导出 CSV、财务报表（月收入/退款/净收入）
- 工单系统（客户提交→客服回复→邮件通知）
- 公告/版本发布管理
- 客户标签与备注（销售跟进）
- 自动续费（签约代扣或余额）
- 授权转移/设备数套餐（1/2/3 台）

### P2（增长）
- 分销/代理体系（分佣、专属折扣码）
- 开放 API（客户自建系统查询授权）
- 状态页（服务可用性）
- 多语言（英文用户端）
- 移动端适配/小程序
- 客户成功看板（活跃度、流失预警）

## 二、架构与安全建议

### 数据层
- 短期：SQLite（现）→ 加 WAL、每日备份、订单表唯一索引；单机够用
- 中期：MySQL/PostgreSQL + Redis（会话/限流/队列），方便多实例与报表
- 定时任务：到期提醒、自动续费、对账、备份（cron + 队列）

### 安全清单
- 密码：bcrypt/argon2（已用 password_hash）；登录限流 + 失败锁定（已有登录尝试表）
- 后台：2FA、CSRF（已有）、IP 白名单可选、操作审计（已有 audit）
- 密钥：易支付 KEY/SMTP 密码加密存储（当前明文，建议 AES + 环境密钥）
- 回调：验签 + 金额校验 + 订单状态机 + 幂等
- 授权 token：HMAC 签名 + 机器码 + 到期（已实现）
- 备份：每日异地备份，保留 30 天
- 传输：HTTPS/HSTS；后台路径可改

### 订单状态机
```
created → pending → paid → licensed → (refunded / revoked)
                ↘ failed / expired
```
