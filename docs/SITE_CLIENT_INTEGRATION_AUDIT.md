# 网站 ↔ 软件 对接完整性检查报告（2026-11-25）

> 范围：`https://license.moneyfly.club`（v3 授权中心后台/门户/API）与 AuroraList 桌面客户端（`src/aeclone`，仓库当前版本号 1.0.10 重建版）之间的全部接口、状态与业务闭环。
> 方法：直接调用生产接口 + 用客户端模块（`license_server` / `licensing` / `report` / `heartbeat` / `updater`）对生产跑真实请求；浏览器验证网站页/购买/工单/解绑；服务端日志与数据库抽样核对。

## 一、结论

核心对接是通的：**注册/登录 → 登录自动绑机 → 授权 token 下发 → 平台解锁 → 购买/续费 → 客户端刷新生效 → 设备管理/解绑 → 心跳与日志归户 → 旧客户端过渡兼容 → 版本更新** 全链路已验证。

本轮检查发现并修复了 **5 个真实对接缺口**，其中 3 个已部署到生产（版本检查接口、账号禁用/设备解绑即时生效、管理后台更新设置），2 个在客户端代码（下次构建生效：心跳生命周期、失效 token 清理）。另发现 1 个**发版策略风险**（版本号仍为 1.0.10，老客户端收不到更新提示），需要你决定是否升版本号。

## 三、本轮修复的缺口（已部署/已改代码）

1. **版本检查接口缺失（已部署）**
   - 现象：客户端 `updater.check` 回退接口 `/api/version/check` 404，GitHub 不可达时没有更新提示。
   - 修复：新增服务端 action + nginx 路由 + `index.php` 兼容路径；后台系统设置新增「客户端更新」（最新版本号、下载地址、SHA256、更新说明）。
2. **账号被禁用后授权仍可下发（已部署）**
   - 现象：后台禁用账号只拦登录，已登录/缓存客户端仍可取 token。
   - 修复：`entitlement_for_machine` / `user_for_machine` 校验账号状态；entitlement 返回 `disabled:true`；旧客户端 verify 返回“账号已被禁用”。
3. **后台解绑设备后客户端仍可离线使用 7 天（已部署 + 客户端代码）**
   - 现象：服务端已无绑定，客户端刷新失败仍保留缓存。
   - 修复：服务端明确返回 `bound:false`；客户端 `refresh_entitlements` 遇到“未绑定/禁用”立即清 token 锁定；纯网络故障仍保留 7 天宽限（不误锁）。
4. **心跳在未登录/退出登录后仍运行（客户端代码）**
   - 现象：后台可能把已退出登录的设备显示为在线。
   - 修复：心跳改为“登录成功后启动、退出登录停止”；未登录不上报。
5. **后台设置页缺版本配置入口（已部署）**
   - 已在 系统设置 →「客户端更新」提供 4 个字段，可按版本发布控制更新提示。

## 四、仍需你决策/人工闭环

1. **版本号策略（重要）**：仓库当前 `src/aeclone/__init__.py`、`app.spec`、`installer.iss` 都是 **1.0.10**（11-25 11:35 提交时明确“版本号保持 1.0.10 重建”）。
   - 后果：已安装的旧 1.0.10 客户端不会收到“新版本”提示（同版本号），也无法通过自动更新升级到“强制登录/设备管理”版本；只能手动发安装包。
   - 建议：新构建至少升到 **1.0.11**（或 1.1.0）并同步三处版本号 + GitHub Release tag；同时把后台「最新版本号」改为同一版本。需要的话我可以直接改好。
   - 当前生产 `latest_version` 已设 1.0.10，避免与服务端回退接口产生“假更新”弹窗。
2. **真实易支付回调**：已用真实 epay 配置 + 合法签名模拟回调验证履约；建议上线后发一笔 **0.01 元**订单做最终联调。
3. **SMTP 邮件**：注册验证码/找回密码依赖 SMTP（沿用旧配置），当前 `require_verify=0` 未强制；建议在后台点“发送测试邮件”验证一次。
4. **客户端发布**：本轮客户端改动（心跳生命周期、缓存清理、设备管理、强制登录）需要重新构建安装包后才会对客户生效。
5. **旧客户端兼容开关**：`legacy_verify_compat=1` 目前让 v1.0.8 等旧客户端继续可用；全部客户升级后可关闭。
