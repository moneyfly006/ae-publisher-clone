# 刊登数据统计（v3 · 2026-11-25 第二轮调整）

## 一、调整结论

1. **后台不再记录/展示产品名称**：只保留“按天 + 平台 + 客户”的刊登成功/失败/总数/成功率统计与趋势。
   - 新库已删除 `product_status` 表（生产已 `DROP TABLE`，历史产品行一并清除）。
   - 心跳里的 `payload.products`（含标题）现在服务端**安全忽略**，不解析、不落库，客户端无需改动。
   - 后台 `/admin/publish` 去掉“最近刊登产品”区块；客户详情去掉产品表，只留刊登汇总/分平台/趋势。
2. **客户端继续上报统计数据**（不含产品名）：心跳 `payload.publish = {平台:{success,fail}}`（今日累计、跨天重置、服务端同日取 max 防重启回退）。
3. **用户端（客户门户）新增「我的刊登数据」**：账号中心左侧导航新增入口，客户可看自己的刊登成功/失败/成功率、按天趋势、按平台明细。

## 二、数据模型

`publish_daily(id, user_id, machine_code, platform, date, success, fail, total, updated_at)`
- 唯一键 `(user_id, platform, date)`；`date` 为 Asia/Shanghai 日期。
- 心跳上报同日多次时按 `max(success)、max(fail)` 合并，`total = max(success)+max(fail)`，避免客户端重启计数回退。
- 历史数据保留（趋势用），不自动删除。

## 三、后台可见位置（管理员）

| 位置 | 内容 |
|---|---|
| 概览 `/admin` | KPI「今日刊登成功 / 今日刊登失败 / 近 7 日成功率」、刊登趋势双折线、今日平台刊登小表 |
| 刊登统计 `/admin/publish` | 天数 1/7/30/90、平台、客户邮箱/机器码筛选；成功率/失败/总数 KPI；按天趋势；按平台表；客户排行（分页，成功/失败/总计/成功率/最近时间） |
| 客户详情 `/admin/users/{id}` | 左侧子导航「刊登数据」：今日/7日/30日 成功/失败/成功率、按平台分周期表、7 天趋势 |

## 四、用户端可见位置（客户）

- 账号中心左侧导航新增「**我的刊登数据**」→ `/account/publish?days=7|30|90`
  - KPI：刊登成功 / 失败 / 总数 / 成功率
  - 按天趋势（成功/失败双折线）
  - 按平台表（成功/失败/总计/成功率 + 合计）
  - 说明：数据来自软件心跳上报、账号维度聚合、**不含商品名称与详情**
- 账号总览 `/account` 新增轻量卡：今日成功/失败、近 7 日成功率 + 7 天 sparkline + 「查看详情」。

## 五、数据来源与限制

- **实时统计**：客户端心跳（需客户端包含“刊登计数”改动的版本，即本次构建之后发布的新版；旧版客户端不发送成功/失败拆分）。
- **历史数据**：已从旧系统诊断事件与 `usage_events` 回填（成功 6138 / 失败 417，覆盖 2 个可映射客户）；旧系统身份映射不全，匿名历史无法归户。
- 旧客户端心跳里的 `platforms[].today` 只有总数、无成功/失败拆分，仅作 total 兜底。
- 不记录产品名称/标题/详情，满足“只记录数据”的要求。
