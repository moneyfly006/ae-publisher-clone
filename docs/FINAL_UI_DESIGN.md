## 🔍 关键发现（从代码分析）

### 1. 店小秘的商品状态流转

```python
# 从 dianxiaomi.py 分析得出
商品状态:
  draft (草稿) → editingRequired (待发布) → onSelling (在线)
                     ↓
              publishFail (发布失败)
```

**关键点**：
- `draft` 状态的商品可以随时编辑（不会被"审核中"阻塞）
- `editingRequired` 状态可能会被平台审核阻塞
- 店小秘用 `dxmState` + `dxmOfflineState` 两个参数区分状态

### 2. 实际的 API 调用流程

```python
# 从 collect_automation.py 分析得出
实际处理流程:
1. snapshot() - 读取采集箱商品列表
2. client_for(platform) - 创建平台客户端
3. settings(cfg, platform) - 读取配置
4. isolated_config() - 隔离配置（避免泄露）
5. 批量处理商品
6. 保存结果
```

### 3. 配置覆盖机制（collect_overrides）

```python
# 从代码中发现的核心设计
alibaba_collect_overrides: {
    "category_id": "统一类目",
    "price": "统一价格",
    "attributes": {"brand": "统一品牌"},
    # ... 更多覆盖项
}
```

**这是关键设计**：
- 用户设置的"处理规则"实际上是 `{platform}_collect_overrides`
- 在批量处理时，这些规则会覆盖商品原有数据

### 4. 店小秘的端点结构

```python
# 从 ENDPOINTS 分析
核心端点:
  product_list - 商品列表（带分页、筛选）
  product_detail - 商品详情（编辑器加载）
  product_save - 保存商品（multipart/form-data + ZIP）
  category_attributes - 类目属性
  batch_publish - 批量发布
  get_offline_counts - 各状态数量统计
```

## 🎯 基于实际情况的 UI 设计

### 核心理念

1. **状态优先**：UI 按商品状态组织（草稿、待发布、发布失败、在线）
2. **配置覆盖**：用 `collect_overrides` 机制统一配置
3. **批量优先**：默认批量处理，单品编辑作为辅助功能
