# 运行日志失败分析与修复（2026-11-23）

## 日志中的失败

### 1. 商品 220114600917618088
```
SKU 109004917084 与 109004917085 的规格属性组合重复
```
根因：模板带 Voltage/plug 属性时，`api_save.merge_skus` 把**整个 SKU 属性列表**
替换成模板属性，导致商品自己的型号属性（YG-GS50/GS130/...）被覆盖，多个 SKU
变成同一组合，被保存前唯一性校验拦下。

修复：
- 标准 SKU（有 skuPropertyId）缺 plug 时，只**追加**模板的 plug/Voltage 属性，
  保留商品自己的型号属性；
- 非标准 SKU 仍沿用模板标准变种（保持原行为）；
- `build_ai_overrides` 的同类逻辑也改为“只追加 plug”，避免同样问题。

验证：
- 用真实商品 088 + 当前模板验证 `merge_skus`：8 个 SKU 全部唯一，
  型号 YG-GS50…GS430 保留，plug 属性已补齐；
- 回归 `test_sku_write_safety` 新增用例通过；
- `test_api_save` 34/34、`test_smt_publish_fixes` 全部通过。

### 2. 商品 220114600914598328
```
区域调价配置存在，但 nationalPriceMode 缺失/非法（isv.7CHK_BASIC_ONEOF）
```
这是**商品数据问题**，不是代码异常；软件在发布前主动拦截，给出两种修复：
- 到店小秘重新保存一次区域调价；
- 或清空区域调价后再发布。
没有自动清空，避免静默改掉你的区域价格。
