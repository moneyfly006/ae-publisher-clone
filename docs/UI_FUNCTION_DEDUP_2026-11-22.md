# 四平台 UI 重复功能整理

Alibaba、Amazon、TikTok、Shopee 的普通功能页已合并重复规则，速卖通保持原导航、页面和发布流程。

| 重复或混淆处 | 整理后 |
|---|---|
| 自动设置和单品高级编辑各有文案提示词、预设 | 提示词只在对应文案页的自动处理设置编辑；当前商品生成使用相同规则 |
| Amazon、TikTok 单品 AI 开关与自动文案开关各自生效 | 对应功能页共用一个开关；旧综合工作台仅作内部兼容，不在普通导航显示 |
| 单品图片区再次设置预设、图片序号和提示词 | 图片规则只保留一处；当前商品按钮读取最新规则后处理并回填 |
| Amazon 额外 SKU / 属性提示词与批量提示词并列 | SKU 规则归 SKU 页，属性规则归类目页；Amazon 当前商品 SKU 共用该规则并附商品 ID，旧配置数据保留 |
| Alibaba 公司、贸易页还有另一套旧批量默认资料 | 通用资料统一在自动设置；单品区保留来源、分组、FOB、阶梯价、包装、交期、库存和已有变种等字段 |
| Alibaba 发布队列与保存发布两入口 | 导航只保留保存发布；旧队列路由自动转到同一页面，导航搜索“队列”也定位此页 |
| 媒体页两次出现图片工作台按钮 | 每个媒体功能页保留一个入口；工作台的手工取图、输出等独立用途继续保留 |

自动处理与当前商品编辑的作用范围仍然分开：前者逐件读取采集箱并应用规则，后者只修改当前商品。没有将某件商品的文案、价格或库存改成批量默认值。概览和侧栏的快捷入口复用同一目标页面。

## 验证

- `tools/test_offline.py`：1168 项通过，含速卖通回归、切页保存、自动处理、平台隔离与新增 7 项去重行为测试。日志：`build/ui-redesign/dedup-regression-final.log`。
- 实际控件树：四平台分别保留 6 / 7 / 7 / 5 个提示词编辑器，每项只有一个功能页归属。明细：`ui-function-dedup-verification.json`。
- 按钮审计：60 页、1211 个回调、0 异常。873 项同步完成，279 项延后后台任务，8 项原生对话框，51 项外部入口；后几类不表示远程调用已成功。记录：`build/ui-redesign/dedup-buttons.json`。
- 设置检查：494 项配置保存、153 项本地控件变化，共 647 次，0 异常。记录：`ui-options-verification.json`。
- 静态控件审计：无缺失点击事件、占位回调、未使用布尔项或当前配置冲突。记录：`control-audit.json`。
- 11 个变更页实际渲染通过，分别检查 1280 和 1024 宽度：Alibaba 3/5/31/32，Amazon 19/20/34，TikTok 26/27，Shopee 41/42。截图及结果位于 `build/ui-redesign/visuals/`。
- 预览曾因浏览器下载官方 CanvasKit WASM 卡住而失败；缓存对应引擎版本的官方资源后重新验收通过。缓存仅用于本地预览，不进入软件包。
- 四阶段安装包均完成测试、构建、签名检查及 `--verify-local` 自检。最终包分别启动四平台原生页面，均无运行错误日志。
