# Alibaba 采集箱批量处理：错误排查与修复（2026-11-22）

用户截图日志：批量 2/10 成功，其余失败：
1. `必填属性「Type」的值「Pool」候选值存在歧义: Heated Pools / Residential Pools / ...`
2. `Type 的值「Container swimming pool」不在平台候选中`
3. `类目 202107201 属性/schema 读取失败：Could not find a suitable TLS CA certificate bundle`

## 根因

- 采集箱里 24 个商品都是**泳池类目 202107201**，而当前推荐/预设是**机械类 127726092**；
  批量没有按类目过滤，直接拿机械预设去处理泳池商品，造成大量属性校验错误。
- 这些泳池商品原有 `Type` 属性值与平台候选枚举不精确匹配，校验层会阻断。
- 打包版里 certifi 根证书路径失效，Alibaba 类目/schema 请求没有系统 CA 兜底。

## 修复

1. **批量按目标类目过滤（默认开启）**
   - 新增「批量处理的目标类目」与「只处理当前推荐类目」开关；
   - 目标类目与商品类目不同的商品直接标记 `⏭ 跳过`，并提示原因；
   - 关闭开关后可处理其他类目，但仍**保留每个商品自己的类目**，不会统一改类目。
2. **TLS CA 兜底**
   - `AlibabaClient` 初始化时优先 certifi，文件不存在则退回系统 CA；
   - 修复打包版「Could not find a suitable TLS CA certificate bundle」。
3. **失败不中断**
   - 单条商品失败只记录在该条，批量继续；完成统计「成功/跳过/失败」。

## 验证

- 用真实软件对象跑当前采集箱（24 个泳池商品，目标机械类）：
  `批量完成：成功 0 / 跳过 10 / 失败 0`，全部为类目差异跳过，不再刷错误。
- 机械类商品（同类目）批量逻辑：单元测试 `tests/test_alibaba_batch.py` 通过
  （匹配类目处理、跳过、类目保留、单条失败不中止）。
- 单条真实保存/发布此前已验证：保存草稿成功；评分 ≥4.5 的机械商品发布 `publishSuccess`。

## 追加修复（同一天，针对“全部跳过/发布预检失败”）

1. **取消默认类目跳过**
   - 批量默认不再按目标类目跳过商品；过滤开关改为可选（默认关闭）。
   - 每个商品使用自己的类目，并按该类目自动补齐必填属性；
   - 实测当前采集箱：`批量完成：成功 2 / 跳过 0 / 失败 0`。

2. **必填属性自动修正 + 去重**
   - 商品原值不在平台候选枚举时，自动换成合法候选（优先通用值），并标记「自动补属性，请复核」；
   - 同一属性存在中英文两行时统一成平台规范英文名，并只保留一行；
   - 修复了 Core Components 残留 Other 导致评分掉到 4.18 的问题，评分恢复 4.60。

3. **发布预检把真实原因显示出来**
   - 以前只显示“发布预检未通过”和视频提示，不显示 `issues`；现在把属性/类目等阻断原因逐条列出。

4. **实测发布成功**
   - 机械商品 `220114598435132626`：评分 4.60 → 确认发布 → 平台状态 `online / publishSuccess`。
